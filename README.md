# CLASSIFIED: LAURA // ДЕЛО №001

Законченный мобильный мини-квест: доступ к архиву → игровое сканирование → личное дело → три вопроса → рассекречивание и тёплый финал. React, TypeScript, Vite, Tailwind CSS, GSAP и Lucide React. Работает полностью в браузере, без backend, ключей и внешних запросов. Шрифты включены в сборку.

## Запуск

Готовая сборка уже находится в `dist/`. На этом Mac можно дважды нажать **`Запустить.command`**: откроется сайт, а локальный сервер будет работать, пока открыто окно терминала. Для этого способа используется установленный Python 3; Node.js не нужен. Из терминала: `python3 scripts/serve.py`.

Для разработки и пересборки:

Понадобится Node.js 22 LTS и npm.

```sh
npm install
npm run dev
```

Откройте адрес, указанный Vite (обычно `http://localhost:5173`). Для проверки на телефоне в той же локальной сети используйте Network URL из терминала.

```sh
npm run build
npm run preview
```

Production-сборка появится в `dist/`. Команда build сначала проверяет TypeScript. Нельзя открывать `index.html` двойным щелчком: нужен HTTP-сервер.

## Что можно настроить

- `src/config/dossierData.ts` — имя, тексты, результаты анализа, заметки, все вопросы и ответы, мемные уведомления и финальные сообщения.
- `src/styles/index.css` — оформление, мобильные размеры и reduced motion.
- `public/images/laura-final-art.png` — предоставленный оригинальный портрет. Он уже подключён, скопирован без изменений, показывается целиком и не обрезается. Исходный файл в корне сохранён.

Пять экранов находятся в `src/screens/`. Общие элементы, эффекты и хуки вынесены отдельно. GSAP-анимации очищаются при размонтировании; приложение работает в React StrictMode.

## Поведение

- Каждый ответ теста принимается; итог всегда шуточный — 999%.
- Прогресс, ответы и завершение сохраняются в localStorage с ключом `classified-laura-progress-v1`. Перезагрузка продолжает историю с последнего этапа, а в тесте — со следующего неотвеченного вопроса. При запрете хранилища всё работает в памяти.
- Кнопка назад возвращает на предыдущий этап. Кнопка в шапке открывает подтверждение сброса, а после завершения можно сразу повторить историю.
- Пять нажатий на слово «пенсия» в заметках агента открывают пасхалку.
- Терминал, сканирование, анализ результата и финальное раскрытие можно пропустить. При `prefers-reduced-motion` движение отключается.
- Звук по умолчанию выключен. Он синтезируется Web Audio только после включения кнопкой в шапке.
- Сканер — визуальная шутка: приложение не запрашивает камеру, микрофон, биометрию, разрешения или персональные данные.
- Нет аналитики, трекеров, настоящей авторизации или сетевых API. localStorage остаётся на устройстве.

## Запуск в Docker

Понадобится Docker с запущенным Docker Desktop или Docker Engine. Node.js на хосте не требуется: многоэтапный Dockerfile устанавливает зависимости через `npm ci`, проверяет TypeScript и собирает приложение внутри образа. Готовую статику отдаёт Nginx от пользователя `nginx`, на порту 8080.

Готовый образ `classified-laura:latest` уже собран для `linux/amd64` и `linux/arm64`. Его переносимая копия — `classified-laura-image.tar.gz` (около 57 МБ). На другом компьютере загрузите её командой `docker load -i classified-laura-image.tar.gz`, затем выполните `docker compose up -d` из папки проекта. Контрольная сумма архива находится в `classified-laura-image.tar.gz.sha256`.

Сборка и запуск через Compose:

```sh
docker compose up --build -d
```

Откройте `http://localhost:8080`. Остановка: `docker compose down`.

Или напрямую:

```sh
docker build -t classified-laura:latest .
docker run -d --name classified-laura -p 8080:8080 --restart unless-stopped classified-laura:latest
```

Проверка состояния: `docker inspect --format '{{.State.Health.Status}}' classified-laura`. Остановка и удаление контейнера: `docker rm -f classified-laura`.

Чтобы перенести образ без реестра:

```sh
docker save classified-laura:latest | gzip > classified-laura-image.tar.gz
# На другом компьютере:
gzip -dc classified-laura-image.tar.gz | docker load
```

Архитектура обычной сборки совпадает с архитектурой Docker-хоста. Для сервера x86-64 можно явно собрать образ командой `docker buildx build --platform linux/amd64 --load -t classified-laura:latest .`. Для ARM64 используйте `--platform linux/arm64`.

Обе платформы в одном образе: `docker buildx build --platform linux/amd64,linux/arm64 --load -t classified-laura:latest .`. Для локальной загрузки такого образа нужен Docker с хранилищем образов containerd. Frontend собирается на архитектуре сборщика; статические файлы одинаково работают на обеих целевых платформах.

## Домен alt-tyanka.ru и HTTPS

Для собственного Linux-сервера подготовлены `compose.production.yaml`, внешний Nginx на портах 80/443 и скрипты Certbot. Приложение работает во внутренней сети без публичного порта 8080. Полная инструкция по DNS, первому запуску и продлению сертификата — в [deploy/README.md](deploy/README.md).

После настройки A-записи домена на IP сервера запустите на сервере:

```sh
bash scripts/init-https.sh you@example.com
```

Замените email на свой. Скрипт включает `https://alt-tyanka.ru`; автоматическое продление настраивается через cron по инструкции. Публичное размещение не выполняется локальным `Запустить.command`.

## Публикация на Vercel

1. Загрузите исходники в Git-репозиторий и импортируйте его в Vercel.
2. Framework Preset: **Vite**. Install command: `npm ci`. Build command: `npm run build`. Output directory: `dist`.
3. Выберите Node.js 22 и опубликуйте проект. Переменные окружения не нужны.

## Публикация на Cloudflare Pages

1. Подключите Git-репозиторий в Pages.
2. Build command: `npm run build`. Build output directory: `dist`. Root directory: корень проекта.
3. Установите `NODE_VERSION=22` в окружении сборки и запустите deployment.

Можно также загрузить готовую папку `dist` через Direct Upload. В приложении нет серверных маршрутов; все этапы переключаются локально на одной странице. Настройки rewrite не требуются. Заголовок noindex отключает индексацию, но не ограничивает доступ: опубликованную ссылку сможет открыть любой, у кого она есть.

## Браузерная проверка

```sh
npx playwright install chromium webkit
npm run test:e2e
```

Playwright сам поднимет dev-сервер или использует уже работающий на порту 5173. Проверяются полная история на 320, 375, 390, 430 и 1440 px, все девять вариантов ответов, портрет, пасхалка, отсутствие горизонтального скролла и ошибок консоли, возврат, повторное прохождение, восстановление прогресса, повторные нажатия и работа без localStorage. Браузеры: Chromium и WebKit. WebKit полезен для проверки Safari-совместимости; поведение Telegram и настоящего iPhone дополнительно проверяется на устройстве.

Для проверки уже запущенного контейнера используйте `PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e`. В этом режиме отдельный Vite-сервер не запускается.
